# Отчёт: метрики приложения в VictoriaMetrics

В кластер minikube, где работает приложение URL Shortener (frontend на nginx, backend на Go, PostgreSQL) и сбор логов
из прошлого задания, установлена VictoriaMetrics single из helm-чарта. Метрики backend и PostgreSQL собираются по
pull-модели, таргеты находятся через service discovery по аннотациям `prometheus.io/*` на подах.

## 1. Стек

| Компонент | Версия | Роль |
|---|---|---|
| minikube / Kubernetes | v1.39.0 / v1.37.0 | кластер (драйвер `docker`, runtime `docker`) |
| VictoriaMetrics single (helm-чарт `vm/victoria-metrics-single`) | чарт 0.49.0, VictoriaMetrics v1.154.0 | TSDB и встроенный скрейпер (`server.scrape`), namespace `monitoring` |
| backend | Go 1.26, gin, `prometheus/client_golang` v1.24.1 | метрики рантайма, HTTP, пула соединений и бизнес-метрики на `:9090/metrics` |
| `IBM/pgxpoolprometheus` | v1.1.3 | коллектор статистики пула соединений pgx |
| `prometheuscommunity/postgres-exporter` | v0.20.1 | экспортер PostgreSQL, сайдкар в поде `postgres-0`, `:9187/metrics` |


- добавлено задание `kubernetes-pods` в `server.scrape.extraScrapeConfigs`. Values из инструкции полностью
  заменяют стандартный `server.scrape.config` чарта и оставляют только `victoriametrics`, `kubernetes-apiservers`,
  `kubernetes-nodes` и `kubernetes-nodes-cadvisor`. Задание, которое находит поды по аннотациям, при этом пропадает,
  поэтому оно добавлено обратно (взято из стандартных values чарта) плюс метка `container`;

- Отдельного vmagent в этой схеме нет: по инструкции метрики собирает сам vmsingle (`server.scrape.enabled: true`). 
  Поэтому состояние таргетов смотрится на порту 8428 (`/targets`, `/api/v1/targets`), а не на 8429 у vmagent.

## 2. Экспортеры

### 2.1. Встроенные в приложение: рантайм Go, процесс, пул соединений, HTTP

Метрики backend отдаются на **отдельном порту 9090** (`METRICS_PORT`), не на порту API 8080:
- порт 9090 не указан ни в Service `backend`, ни в nginx, поэтому снаружи кластера `/metrics` недоступен. Его читает
  только VictoriaMetrics по IP пода, авторизация не нужна;
- оба HTTP-сервера останавливаются вместе при graceful shutdown.

| Источник | Библиотека | Примеры метрик |
|---|---|---|
| рантайм Go | `client_golang` `collectors.NewGoCollector` | `go_goroutines`, `go_memstats_heap_alloc_bytes`, `go_gc_duration_seconds` |
| процесс | `collectors.NewProcessCollector` | `process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds` |
| пул соединений pgx | `IBM/pgxpoolprometheus` | `pgxpool_acquired_conns`, `pgxpool_idle_conns`, `pgxpool_max_conns`, `pgxpool_empty_acquire` (сколько раз пришлось ждать свободное соединение), `pgxpool_acquire_duration_ns` |
| HTTP (gin) | своя middleware на `client_golang` (`internal/controller/middleware/metrics.go`) | `http_request_duration_seconds{method,route,status}` (гистограмма, её `_count` - число запросов), `http_requests_in_flight` |
| сам эндпоинт метрик | `promhttp.InstrumentMetricHandler` | `promhttp_metric_handler_requests_total` |

### 2.2. Готовый внешний экспортер: postgres-exporter

`postgres-exporter` добавлен вторым контейнером в под `postgres-0`:
- контейнеры пода делят сетевое пространство, поэтому экспортер подключается к `localhost:5432`;
- логин и пароль берутся из существующего Secret `postgres-credentials`, имя базы - из ConfigMap;
- новые секреты не нужны, в YAML паролей нет.

Примеры метрик:
- `pg_up` - удаётся ли экспортеру подключиться к базе;
- `pg_stat_database_numbackends` (подключения), `pg_stat_database_xact_commit`, `pg_stat_database_xact_rollback`;
- `pg_stat_database_tup_inserted`, `pg_stat_database_tup_deleted`, `pg_database_size_bytes`;
- `pg_settings_max_connections`.

## 3. Бизнес-метрики

Считаются в слое usecase (`internal/usecase/link`)

| Метрика | Тип | Метки | Что считает |
|---|---|---|---|
| `urlshort_links_created_total` | counter | `code_source="custom\|generated"` | созданные короткие ссылки: со своим кодом и со сгенерированным |
| `urlshort_redirects_total` | counter | `result="found\|not_found"` | переходы по коротким ссылкам `/r/{code}`: успешные и по несуществующему коду |
| `urlshort_links_updated_total` | counter | - | изменённые ссылки (URL или код) |
| `urlshort_links_deleted_total` | counter | - | удалённые ссылки |
| `urlshort_code_conflicts_total` | counter | `code_source="custom\|generated"` | попытки занять существующий код: `custom` - пользователь получил 409 при создании или изменении, `generated` - коллизия сгенерированного кода, сервис повторил генерацию |
