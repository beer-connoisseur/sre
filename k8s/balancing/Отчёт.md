# Распределение HTTP-трафика между двумя версиями URL Shortener

В minikube настроено распределение запросов через Envoy Gateway с весами 90/10. Из 200 запросов версия `1.0.0` обработала 181, версия `2.0.0` — 19.

## Манифесты Kubernetes

Для обеих версий использованы манифесты из задания по стратегиям развёртывания. Deployment, Service, Gateway и HTTPRoute находятся в пространстве имён `url-shortener`.

## Проверка

Через `kubectl port-forward` локальный порт `8888` был связан с портом `80` входного Service прокси Envoy. Скрипт замера отправил 200 последовательных запросов `GET /healthz` на этот порт. Для каждого ответа скрипт записал HTTP-статус и значение заголовка `X-Version`, по которому определялась версия бэкенда.

| Версия | Заданная доля | Число ответов | Фактическая доля |
|---|---:|---:|---:|
| `1.0.0` | 90 % | 181 | 90,5 % |
| `2.0.0` | 10 % | 19 | 9,5 % |
| **Всего** | **100 %** | **200** | **100 %** |

## Вывод

При весах 90/10 на 200 запросов ожидается в среднем 180 ответов от v1 и 20 от v2. В этом прогоне v1 обработала на один запрос больше, а v2 — на один меньше. Отклонение составило 0,5 процентного пункта для каждой версии. Результат согласуется с настройкой маршрута: веса задают ожидаемые доли трафика, поэтому в отдельной серии возможны небольшие отклонения.
