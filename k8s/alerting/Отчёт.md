# Отчёт: алерты для URL Shortener

К VictoriaMetrics single из прошлых заданий добавлены **vmalert** (вычисляет правила по метрикам) и
**Alertmanager** (группирует и маршрутизирует сработавшие алерты) - helm-чарт `vm/victoria-metrics-alert` 0.51.0 в
namespace `monitoring`. Уведомления приходят в Telegram.

## 1. Какие алерты нужны и почему

Принципы выбора:
- пороги берутся из **SLO прошлого задания** - алерт срабатывает, когда SLO нарушается устойчиво, а не от единичного
  выброса (`for`);
- у каждого алерта есть **severity** (по нему выбирается канал) и **runbook** - что делать дежурному;
- рантайм-алерт предупреждает о проблеме **до** того, как она станет симптомом.

| Алерт | Метрики | Severity | Тип |
|---|---|---|---|
| `ProberFailing` | `urlshort_prober_runs_total` | critical | сервис |
| `HighErrorRate` | `http_request_duration_seconds_count` | critical | сервис |
| `SlowRedirects` | `http_request_duration_seconds_bucket` | warning | сервис |
| `BackendMemoryHigh` | `process_resident_memory_bytes` (рантайм Go) + `container_spec_memory_limit_bytes` (cAdvisor) | warning | рантайм |

### ProberFailing - сценарий пользователя не проходит

```
sum(rate(urlshort_prober_runs_total{result="success"}[2m]))
  / sum(rate(urlshort_prober_runs_total[2m])) < 0.99      for: 2m
```

- Главный симптом - пробер раз в 10 секунд выполняет то же, что пользователь (создать ссылку → перейти →
  удалить) через frontend. Если сценарий не проходит, сервисом нельзя пользоваться.

### HighErrorRate - доля 5xx выше SLO

```
sum(rate(http_request_duration_seconds_count{app="backend", route!~"/healthz|/readyz", status=~"5.."}[5m]))
  / sum(rate(http_request_duration_seconds_count{app="backend", route!~"/healthz|/readyz"}[5m])) > 0.01      for: 5m
```

- Нарушение SLO 1 (не более 1 % серверных ошибок) по всему реальному трафику, а не только по сценарию
  пробера - ошибки могут быть в эндпоинтах, которые пробер не трогает (список ссылок, изменение).

### SlowRedirects - переходы по ссылкам замедлились

```
sum(rate(http_request_duration_seconds_bucket{app="backend", route="/r/:code", le="0.25"}[5m]))
  / sum(rate(http_request_duration_seconds_count{app="backend", route="/r/:code"}[5m])) < 0.95      for: 5m
```

- Переход по короткой ссылке - основной сценарий, SLO 2: 95 % быстрее 250 мс.

### BackendMemoryHigh - память процесса близко к лимиту (рантайм)

```
max by (namespace, pod) (process_resident_memory_bytes{app="backend"})
  / max by (namespace, pod) (container_spec_memory_limit_bytes{namespace="url-shortener", pod=~"backend-.+"}) > 0.9      for: 5m
```

- При достижении лимита (128Mi) ядро убьёт процесс (OOMKill), под перезапустится, запросы на нём
  оборвутся. Алерт на 90 % даёт время разобраться до этого (утечка памяти, рост горутин, слишком маленький лимит).
